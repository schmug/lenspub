# Design Principles

**Status:** Draft v0.1 · **Date:** 2026-07-09 · **License:** CC-BY 4.0

The [constitution](../constitution/DESIGN_HANDOFF.md) fixes ten guiding principles that every LensPub document and every conforming implementation is expected to reinforce. This document develops each one: what it means, what it concretely demands of the protocol (with the Architecture Decision Record that anchors the demand), and one design temptation it forbids — because a principle that forbids nothing decides nothing. The closing section explains how the principles trade off against one another and which prevails where. This is a vision-level document; the binding requirements live in the [specifications](../spec/lenspub-protocol.md) and [ADRs](../adr/README.md).

## 1. User ownership

The interpretation layer belongs to the person it serves — as possession, not license. Ownership here is literal: the user holds the artifact, can read and modify it without permission, and no other party can revoke, suspend, or terms-of-service it away. Concretely, the protocol makes the Lens Manifest a self-contained, portable document rather than a record in someone's database ([ADR-0001](../adr/0001-manifest-is-declarative-policy.md)); keeps all Adaptation State device-local ([ADR-0006](../adr/0006-history-free-shareable-core.md)); and makes trust in Lens Publishers explicitly user-granted and revocable ([ADR-0003](../adr/0003-adopt-vc2-dids-for-trust.md)). Forbidden temptation: storing the "real" lens in a vendor cloud account with the device holding only a cache — convenient for sync, and a repossession of the user's property in all but name.

## 2. Transparency

The user can always find out what their lens is and what it is doing; nothing about their own filter is a secret from them. This requires that the manifest be a human-readable declarative policy — never model weights, never a prompt ([ADR-0001](../adr/0001-manifest-is-declarative-policy.md)) — that Lens Diffs carry plain-language summaries of every change, and that the Reproducibility Envelope expose which engine, model, and parameters actually produced each result ([ADR-0004](../adr/0004-reproducibility-envelope.md)). Forbidden temptation: representing learned preferences as an opaque embedding vector because it captures nuance a declarative schema cannot — a real accuracy gain, purchased by making the user's own filter unreadable to them.

## 3. Local-first design

Interpretation runs on the user's device; the network is an enhancement, never a requirement. The protocol sets local-only inference as the hard default, permits remote inference only as an explicit, per-domain, revocable opt-in, and requires engines to fail closed into local capability rather than silently substituting a remote service ([ADR-0005](../adr/0005-local-only-default.md)). The overlay stage itself is defined as user-agent-side ([ADR-0008](../adr/0008-interpretation-is-overlay-stage.md)), so there is no server in the reading path by construction. Forbidden temptation: routing all interpretation through a hosted API because it is simpler to build and yields richer results — recreating, in one step, the surveillance point the protocol exists to remove.

## 4. Explainability

Every act of interpretation can answer the question "why?" Each Overlay Annotation carries a required Reasoning Trace naming the manifest rule, priority, source weight, or signal that triggered it, with pointers back into the manifest ([interpretation-result schema](../schemas/interpretation-result.schema.json)); evidence-class annotations additionally carry a `basis` of checkable facts ([ADR-0007](../adr/0007-epistemic-stance.md)); even the engine's classification of content into Domain Scopes must be explainable ([Glossary](../GLOSSARY.md)). Forbidden temptation: suppressing traces to keep the interface clean, or emitting bare scores ("credibility: 62") with no stated basis — an unexplained number is a verdict wearing a lab coat.

## 5. Reversibility

No decision about a lens is a one-way door. Every accepted Lens Change Proposal produces an immutable, content-addressed Lens Version, and rollback to any prior version is required ([ADR-0004](../adr/0004-reproducibility-envelope.md)); even the small class of auto-acceptable changes is always notified and always rollback-able, unconditionally ([ADR-0010](../adr/0010-adaptation-policies-parameterized.md)); cloud opt-ins and publisher trust are revocable at any time ([ADR-0005](../adr/0005-local-only-default.md), [ADR-0003](../adr/0003-adopt-vc2-dids-for-trust.md)). Forbidden temptation: destructive migration — upgrading a manifest in place to a new format, or letting an auto-accepted change overwrite state that cannot be reconstructed, because keeping history is storage and engineering nobody is asking for until the day they are.

## 6. Portability

A lens moves intact between devices, applications, and implementations. The manifest is model-agnostic by construction ([ADR-0001](../adr/0001-manifest-is-declarative-policy.md)); the five Adaptation Policies are defined as points on explicit parameters so the same manifest produces the same adaptation behavior on every conforming engine ([ADR-0010](../adr/0010-adaptation-policies-parameterized.md)); and where experience legitimately differs between engines, capability tiers make the difference declared rather than hidden ([ADR-0004](../adr/0004-reproducibility-envelope.md)). Forbidden temptation: engine-specific manifest extensions that only their author can interpret — each one a small, deniable step back toward the proprietary filter, dressed as innovation.

## 7. Open standards

LensPub profiles existing standards where they exist and authors new specification only where none does. Overlay and anchoring are a profile of the [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/) ([ADR-0002](../adr/0002-profile-web-annotation.md)); identity, signing, and trust adopt [W3C Verifiable Credentials 2.0, DIDs, and Data Integrity](https://www.w3.org/TR/vc-data-integrity/) ([ADR-0003](../adr/0003-adopt-vc2-dids-for-trust.md)); hosting and federation stay abstract with Solid and AT Protocol as named profiles and bindings, and C2PA is consumed as a Provenance Signal ([constitution, Standards Posture](../constitution/DESIGN_HANDOFF.md)). Forbidden temptation: the bespoke annotation or signature format that is "simpler for our case" — it always is, until the second implementation, the first auditor, and the standards reviewer arrive.

## 8. Privacy by default

Reading is not a data source for anyone. The shareable lens is the history-free manifest core, structurally incapable of containing URLs visited, excerpts, timestamps, or feedback records ([ADR-0006](../adr/0006-history-free-shareable-core.md)); Lens Diffs operate on cores only; inference is local unless explicitly opted otherwise ([ADR-0005](../adr/0005-local-only-default.md)); organizations receive only explicitly consented, aggregated signals. Privacy here is load-bearing for the mission, not a compliance feature: a lens observes exactly what a surveillance economy wants to buy. Forbidden temptation: default-on telemetry to "improve interpretation quality" — the moment reading behavior funds the product, LensPub has become the thing it was built against.

## 9. Vendor neutrality

No model, browser, company, or hosting provider is privileged by the design. The manifest's model-agnosticism ([ADR-0001](../adr/0001-manifest-is-declarative-policy.md)) keeps every engine vendor equal; DID-method choice remains open ([ADR-0003](../adr/0003-adopt-vc2-dids-for-trust.md)); the specification is CC-BY 4.0 and the reference code Apache-2.0, whose patent grant protects independent implementers ([ADR-0009](../adr/0009-licensing-and-governance.md)); and the browser is a proof-of-concept venue, not a dependency — the overlay stage is defined for any user agent ([ADR-0008](../adr/0008-interpretation-is-overlay-stage.md)). Forbidden temptation: specifying against the strongest current model's behavior, or letting the reference implementation's conveniences harden into de facto requirements no second implementer can meet.

## 10. Human agency over automation

Automation proposes; the human decides. Learning is never silent: a lens evolves only through Lens Change Proposals generated from the user's explicit feedback, reviewed under the user's chosen Adaptation Policy, with auto-acceptance capped by the `autoAcceptCeiling` — exceeding it is a conformance violation, and even the Explorer policy never permits an un-notified change ([ADR-0010](../adr/0010-adaptation-policies-parameterized.md)). Forbidden temptation: inferring preferences from implicit signals — dwell time, scroll depth, return visits — because it would make adaptation feel effortless. Effortless adaptation is precisely how the engagement-optimized feed trained its users; LensPub declines the trick even when the user might enjoy it.

## How the principles trade off

Ten absolutes cannot all be absolute at once; the design's character shows in which one yields, and how. The sharpest tension is **local-first versus interpretation richness**: models that fit on a device are weaker than hosted frontier models, so a strictly local lens sees less. The resolution is neither prohibition nor a soft default. Capability tiers ([ADR-0004](../adr/0004-reproducibility-envelope.md)) make the richness gap explicit and declared, and per-domain opt-in ([ADR-0005](../adr/0005-local-only-default.md)) lets a user buy richness with consent, scoped to domains where the trade is acceptable — cloud assistance for technical research, never for health — with the crossing recorded in every Reproducibility Envelope. Local-first wins as the default; richness is available, but only ever as a legible, revocable choice.

**Privacy versus transparency and sharing** is resolved by an asymmetry: the lens is fully transparent *to its owner* — complete history, every trace — and history-free *to everyone else*, because the shareable core structurally cannot carry reading history ([ADR-0006](../adr/0006-history-free-shareable-core.md)). When the two collide, privacy wins toward the world and transparency wins toward the user, and no configuration can swap those directions.

**Human agency versus convenience** is resolved by the parameterized policy spectrum ([ADR-0010](../adr/0010-adaptation-policies-parameterized.md)): users choose how much review burden they carry, from Locked to Explorer, but the floor — notification and rollback — is unconditional. Agency wins; convenience negotiates above the floor, never below it. **Portability versus experience fidelity** is resolved by honesty: manifest portability is guaranteed, experience portability is explicitly not ([ADR-0004](../adr/0004-reproducibility-envelope.md)) — the protocol promises the smaller thing it can keep. And **open standards versus simplicity** is resolved by profiling: adopting W3C Web Annotation and Verifiable Credentials costs implementation weight, which capability tiers absorb by letting minimal engines omit whole features (a rule-based local engine need not implement subscription verification at all) rather than implement them badly.

The general rule beneath these resolutions: when a trade-off touches the user's data or the user's consent, privacy and agency win unconditionally. When it touches capability or richness, the answer is tiering and opt-in — making the trade explicit and the choice the user's — rather than a prohibition the ecosystem would route around. That rule is this document in one sentence: LensPub never resolves a tension by deciding on the user's behalf.
